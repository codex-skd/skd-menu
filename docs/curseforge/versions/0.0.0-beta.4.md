<h2>v0.0.0-beta.4 - Custom loading screen removed</h2>

<p>On a full modpack, the custom loading screen rendered black &mdash; only its progress bar showed &mdash; whenever a server applied its resource pack (and again on disconnect). This build drops the custom loading screen entirely and lets NeoForge's vanilla one handle those reloads. The title-screen customization is untouched.</p>

<h3>Removed</h3>
<ul>
<li><strong>Custom loading-screen overlay (<code>LoadingOverlayMixin</code>).</strong> It replaced the whole vanilla loading overlay, but during an in-game resource reload its textured draws (background, banner, logo, progress-bar frame) rendered nothing &mdash; only <code>GuiGraphics.fill</code> primitives showed, leaving a black screen with a bare progress bar. Diagnostics confirmed the texture resolved to a valid <code>DynamicTexture</code> with a clean GL state; the blits were still swallowed on the overlay code path (the same blit works fine on the title screen), pointing at a <code>GuiGraphics</code> batching interaction with another client mod. Instead of fighting that, the overlay is gone: server-pack reloads now use NeoForge's own loading screen.</li>
<li>Deleted <code>LoadingConfig</code> (the <code>config/skd_menu/loading.json</code> model) and <code>EarlyDisplayInstaller</code> (already a no-op on NeoForge 21.1.x), plus the bundled <code>earlydisplay/</code> theme resources and <code>textures/gui/bar_track.png</code>. <code>TextureResolver</code> and <code>SkdMenuClient</code> are back to their beta.3 state.</li>
</ul>

<h3>Unchanged</h3>
<ul>
<li>The title-screen customization &mdash; background (image / zoom / colour / panorama / animated), two corner logos, title image, button repositioning and hiding, custom buttons, image overlays, and third-party button control &mdash; works exactly as before.</li>
</ul>

<h3>Notes</h3>
<blockquote>Client-only menu mod, no gameplay content. Verified in-game: title screen keeps its custom look; server-pack join / disconnect now shows the vanilla NeoForge loading screen. <code>./gradlew clean build</code> OK. The resource-reload duration itself is unchanged &mdash; that is the modpack (and any shader pack) rebuilding, not this mod.</blockquote>
