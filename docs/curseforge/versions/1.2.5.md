<h2>v1.2.5 - Loading-screen background hardening</h2>

<h3>Fix</h3>
<ul>
<li><strong>Black background on the custom loading screen during a resource reload.</strong> When the background texture's dimensions could not be resolved while the <code>ResourceManager</code> was being rebuilt (<code>TextureResolver.dimensions()</code> returned <code>null</code>), <code>renderCoverImage</code> blitted a 1&times;1 source region stretched to full screen &mdash; a solid near-black rectangle. Dimensions are now read from the classpath first (<code>/assets/&lt;namespace&gt;/&lt;path&gt;</code>, which stays available during a reload), and when still unknown the image is drawn with a plain full-texture stretch blit.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>TextureResolver.cacheDimensionsFromIdentifier</code> &mdash; classpath lookup attempted before the <code>ResourceManager</code>.</li>
<li><code>LoadingOverlayMixin.renderCoverImage</code> &mdash; fallback branch when <code>dimensions()</code> is <code>null</code>.</li>
<li>No change to overlay teardown: on 26.2 the reload-finished logic lives in <code>LoadingOverlay#tick</code> (which the mixin does not replace and which already carries NeoForge's anti-loop guard), so this branch never had the infinite hang that affected the 1.21.1 line.</li>
</ul>

<blockquote>Client-only menu mod, no gameplay content. Verified: <code>./gradlew clean build</code> OK (forced recompile + mixin annotation processor + jar). Not yet reviewed in-game.</blockquote>
