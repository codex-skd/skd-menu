<h2>v0.0.0-beta.3 - Loading-screen reload fixes</h2>

<p>Connecting to a server that applies a resource pack &mdash; or changing a resource pack / shader pack in the options &mdash; froze the game on the custom loading screen. Fixed, along with the black background it showed while frozen.</p>

<h3>Fixed</h3>
<ul>
<li><strong>Custom loading screen never closed on an in-game resource reload</strong> (server resource pack, <code>F3+T</code>, or switching a resource / shader pack from Options). <code>LoadingOverlayMixin</code> replaced <code>LoadingOverlay#render</code> wholesale and cancelled it, but left out vanilla's reload-finished block, so <code>fadeOutStart</code> was never set and the <code>onFinish</code> callback never fired &mdash; the overlay stayed up forever with a black background and a full progress bar. That block is restored (<code>reload.checkExceptions()</code> &rarr; <code>onFinish</code> &rarr; <code>fadeOutStart</code> &rarr; <code>screen.init</code>). Startup was never affected because NeoForge overrides <code>render</code> on its own <code>LoadingOverlay</code> subclass there; only later plain-overlay reloads hit the bug.</li>
<li><strong>Black background on those reload screens.</strong> <code>TextureResolver.dimensions()</code> returned <code>null</code> while the <code>ResourceManager</code> was being rebuilt, and <code>renderCoverImage</code> then blitted a 1&times;1 source region stretched to full screen (a solid near-black rectangle). Dimensions are now read from the classpath first (<code>/assets/&lt;namespace&gt;/&lt;path&gt;</code>, which stays available during a reload), and when still unknown the image is drawn with a plain full-texture stretch blit.</li>
</ul>

<h3>Changed</h3>
<ul>
<li><strong><code>EarlyDisplayInstaller</code> is now a no-op on 1.21.1.</strong> NeoForge 21.1.x / FancyModLoader 1.21.1 has no <code>earlyLoadingScreenTheme</code> config key and no JSON early-display theme system (that arrived in a later NeoForge), so the installer had been writing a key FML strips on every launch and copying unused files into <code>config/fml/</code>. The in-game loading / resource-reload screen is still fully themed; the FML "early window" shown while mods load keeps the vanilla look on this Minecraft version.</li>
</ul>

<h3>Notes</h3>
<blockquote>Client-only menu mod, no gameplay content. Verified: <code>./gradlew clean build</code> OK on both branches (forced recompile + mixin annotation processor + jar). Not yet reviewed in-game against a server resource pack.</blockquote>
